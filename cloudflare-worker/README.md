# Экспериментальное реле Cloudflare Worker

Для пробы маршрута через настоящий Cloudflare edge без VPS и покупки домена.
Совместимо с полем **WSS-реле** TGWS-Android 0.1.3/0.2.0. APK менять не нужно.
[English](../docs/en/CLOUDFLARE_WORKER.md).

**Статус: реализовано и протестировано локально; облачный runtime и Telegram
через Мегафон (Москва/область) не проверены.** Аккаунт Cloudflare и внешний
Worker в текущей среде не подключены. Исходники не означают работающий внешний узел.

## SNI и адрес

Телефон соединяется с `ваш-worker.ваш-аккаунт.workers.dev:443`; TLS SNI и HTTP
Host — это имя Worker. Оператор видит адрес Cloudflare edge и это SNI.
`cloudflare.com` — чужой сайт, а не адрес реле. Его подстановка в SNI не создаёт
TCP-прокси, не меняет заблокированный IP и может привести к отказу сертификата
или маршрутизации CDN. Проверка TLS в приложении остаётся включённой.
Если Мегафон фильтрует и workers.dev/Cloudflare IP, этот путь тоже не сработает.
Пока установлен только факт неудачи прямого пути со слов владельца; механизм
фильтрации, наличие allowlist и результат Worker не установлены.

## Создание узла

1. Создайте/откройте свой аккаунт [Cloudflare](https://dash.cloudflare.com/) и
   подтвердите почту. Прочитайте действующие условия, лимиты и стоимость Workers.
2. На компьютере с Node.js 22+:

   ```bash
   cd cloudflare-worker
   npm ci --ignore-scripts --no-audit --no-fund
   npm run build
   ```

   В `dist/worker.js` будет один готовый модуль для редактора Cloudflare.
   Сборка — dry run, она не публикует Worker и не требует токена Cloudflare.
3. В панели Workers & Pages создайте Worker. В редактор вставьте содержимое
   `dist/worker.js`. Добавьте **Secret** `TGWS_RELAY_TOKEN`: случайные 32–64
   строчных HEX-символа. Например, сгенерируйте 24 случайных байта локально.
   Не вставляйте ключ в исходники, GitHub, логи или этот чат.
4. Опубликуйте Worker и включите доступ по своему `*.workers.dev`. Отключите
   Workers Logs/observability: полный путь запроса содержит ключ. Провайдер
   всё равно обрабатывает IP/домен и трафик; это не обещание отсутствия метаданных.
5. Альтернатива панели — локальный Wrangler: `npx wrangler login`,
   `npx wrangler secret put TGWS_RELAY_TOKEN`, `npm run deploy`.
   Убедитесь, что выбран ваш аккаунт. API-токены остаются на вашем компьютере.

Пример адреса (это **не** действующий сервер):

```text
wss://tgws-relay.account.workers.dev/<ваш-TGWS_RELAY_TOKEN>/apiws
```

В TGWS остановите прокси, вставьте адрес в поле WSS-реле и запустите снова.
Существующие локальный порт и MTProto secret сохраняются. Непустое поле
означает **только реле**, без прямого fallback. URL сохраняется зашифрованным.

## Ограничения этой заготовки

- Только точные пары DC/IP Flowseal v1.11.2 и TCP 443; нет произвольного прокси.
- Ключ пути обязателен. Первое бинарное сообщение — ровно 64 байта init.
- До четырёх соединений **на isolate**, включая закрывающиеся сокеты; это
  не глобальная квота аккаунта и не защита от DDoS/расходов. Настройте квоты аккаунта.
- Connect 6 с, init/write 10 с, idle 5 минут; очередь до 4 MiB + 4 байта,
  до 64 сообщений. Проверка размеров и закрытие ресурсов обязательны.
- **16 MiB суммарно в обе стороны на одну сессию**, затем закрытие с кодом 1008.
  Это явный защитный лимит: Worker WebSocket API не даёт drain/backpressure для
  send, поэтому нельзя обещать ограниченную память при бесконечном потоке.
  Ограничение может вызывать переподключения и мешать крупным загрузкам.
  Эта заготовка предназначена для проверки достижимости/текстовых сообщений,
  а не для заявления об исправленной устойчивости или полноценного media relay.
- Cloudflare сам может закрывать соединения при обновлениях и ограничениях;
  доступ к Telegram из облака, тариф и политика сервиса проверяются отдельно.

Для длительного трафика используйте существующий Node.js relay за Cloudflare
Proxy на своём домене с **Full (strict)** и WebSocket либо отдельный дальнейший
протокол управления потоком. Это потребует домена/origin и отдельной проверки.

## Что действительно проверено

`npm test` из этой папки (сначала `npm ci --prefix ../relay --ignore-scripts`):
маршруты совпадают с origin, запреты URL/DC, ключ/Upgrade, очередь, порядок
байтов, тайм-ауты, budget/закрытие и настоящий локальный TCP echo через
инъекцию платформенных WebSocket/Response. Эти адаптеры не заменяют облачный E2E.
`npm run build` проверяет bundling Wrangler; CI сохраняет модуль и JUnit.

После развёртывания: сначала Wi-Fi, затем **выключить Wi-Fi** и повторить
текст в обе стороны через официальный Telegram. Сравнить счётчик relay,
переподключение и небольшую загрузку. Записать commit APK, Android, дату,
оператора и результат, без URL/ключей. Пинг Telegram не доказывает этот маршрут.

Эталон: [Flowseal v1.11.2 Worker](https://github.com/Flowseal/tg-ws-proxy/blob/v1.11.2/docs/RU/CfWorker.md).
Платформенные API: [TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/),
[WebSockets](https://developers.cloudflare.com/workers/runtime-apis/websockets/).
