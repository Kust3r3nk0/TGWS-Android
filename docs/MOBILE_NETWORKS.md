# Мобильные сети и WSS-реле

> Актуальное поведение 0.3.4: [сети и диагностика](NETWORK_COMPATIBILITY_0.3.4.md). В версиях 0.3+ режим задаётся явно: «Только реле» + URL; одного непустого поля недостаточно. Встроенный Cloudflare DNS удалён.


В прямом режиме телефон открывает WSS к `149.154.167.220` для DC 2/4
или TCP к адресам Telegram DC. Если оператор блокирует эти адреса,
переход WSS → TCP может не помочь. Изменение локального порта `127.0.0.1`
не меняет удалённый адрес. Не каждый тайм-аут доказывает блокировку:
нужны сравнение Wi-Fi/мобильной сети и сведения об операторе.

## Доступный альтернативный маршрут

Для пробы без VPS подготовлен [экспериментальный Cloudflare Worker](../cloudflare-worker/README.md).
Нужен аккаунт Cloudflare; APK 0.2.0 уже совместим. SNI будет именем вашего
Worker, а не `cloudflare.com`. Доступность внешнего узла зависит от сети. У заготовки есть защитный лимит **16 MiB на сессию**, поэтому она
подходит для проверки маршрута/текста, но может прерывать большие загрузки.

В `0.1.3-alpha` добавлен **выбираемый пользователем режим WSS-реле**:

```text
Telegram → 127.0.0.1 → TGWS → TLS/WSS:443 → ваше реле → Telegram DC:443
```

Потребуется внешний узел, чей IP/домен доступен из мобильной сети.
Смена DNS или добавление TLS сами по себе не обходят запрет IP.
Если оператор разрешает только список сайтов, выбранное реле также может
оказаться недоступным. Универсальный обход не гарантируется.

В приложение не встроены публичные сторонние реле. Нужен ваш узел либо
узел доверенного оператора. Реле видит соединения и метаданные; TLS до него
не заменяет сквозную защиту протокола Telegram. URL с ключом доступа не
публикуйте в issue, логах или скриншотах.

## Настройка приложения

1. Остановите локальный прокси.
2. В поле **WSS-реле** укажите, например,
   `wss://relay.example/<случайный-ключ>/apiws`. Это пример, не работающий адрес.
3. Используйте только `wss://`, DNS-имя и порт 443. Query, fragment,
   userinfo и IP-литералы не принимаются. Не вставляйте ссылку `tg://proxy`.
4. Запустите прокси. Старые локальный порт и MTProto secret можно сохранить:
   менять локальную ссылку Telegram при смене внешнего транспорта не требуется.
5. Смотрите счётчик **реле** и проверьте отправку/получение/загрузку через
   официальный Telegram при выключенном Wi-Fi.

**Непустое поле включает только реле**, без скрытого прямого WSS/TCP fallback.
Для возврата к прежнему режиму остановите прокси, очистите поле и запустите снова.
Ошибка реле не отключает проверку сертификата и имени сервера. Одна попытка
ограничена 8 с; потеря сети закрывает сессию, Telegram создаёт новую.
URL хранится в Keystore AES-256-GCM отдельно от MTProto secret, скрыт в UI,
не входит в сохранённое состояние Activity и диагностику. Потеря ключа требует
явного восстановления: укажите URL реле заново, иначе выбирается прямой режим.

## Совместимость с Flowseal v1.11.2

Контракт соответствует `proxy/bridge.py::_cfproxy_worker_fallback`:
`GET /apiws?dst=<DC_DEFAULT_IPS[dc]>&dc=<dc>`, затем первое бинарное
сообщение — исходящая 64-байтовая relay initialization, далее поток Obfuscated2.
Media использует абсолютный DC, как upstream. DC 1–5 и 203 поддерживаются;
тестовые DC не добавлены. Дополнительный защищённый префикс пути — расширение
собственного реле; для существующего совместимого Worker укажите его путь
`/apiws`. Cloudflare Worker должен сам уметь пересылать WSS в TCP Telegram;
обычный сайт или произвольный Worker не подходит.

Изменение не включает пулы, автоматический подбор чужих узлов, Fake TLS,
маскировку под сторонний домен или отключение проверки TLS.

## Сервер реле для собственного хоста

В [relay/](../relay/) есть самостоятельный Node.js сервер. Он не входит в APK
и не требует Node.js на телефоне. Это вариант для VPS, доступного из нужной сети;
само наличие исходников сервера не создаёт доступный внешний узел.

Нужны Node.js 22+ и доверенный TLS-сертификат для вашего домена. Пример
подготовки на сервере, без вывода ключей в журнал:

```bash
cd relay
npm ci --omit=dev --ignore-scripts
# Создайте закрытый файл с ключом доступа, права 0600; не добавляйте его в Git.
openssl rand -hex 24 > /secure/tgws-relay-token
export TGWS_RELAY_TOKEN="$(cat /secure/tgws-relay-token)"
export TGWS_TLS_KEY=/secure/privkey.pem
export TGWS_TLS_CERT=/secure/fullchain.pem
npm start
```

Процесс слушает TCP 443. Для низкого порта настройте права средствами своей
ОС/сервис-менеджера; не запускайте npm с root-правами по умолчанию. Настройте
автозапуск, обновление сертификата и firewall. В приложение введите
`wss://ваш-домен/<значение TGWS_RELAY_TOKEN>/apiws`.
Ключ пути и MTProto secret — разные значения. Сервер проверяет ключ до TCP dial,
разрешает только точные пары IP/DC Flowseal, ограничивает сессии, размеры,
тайм-ауты и использует stream backpressure. Содержимое пакетов и URL не логируются.

Cloudflare Proxy перед вашим origin — возможный отдельный способ изменить
внешний IP телефона; origin должен иметь корректный сертификат, а Cloudflare
SSL/TLS — режим **Full (strict)** с поддержкой WebSocket. Это требует вашего
домена/аккаунта и проверки доступности edge IP у оператора. Удалённый деплой,
Cloudflare Proxy/Worker и трафик реального оператора в этой среде **не проверены**.

## Проверки и оставшееся

- JVM: валидация URL, GCM/AAD, маршрутизация DC/media, сохранение AES-CTR,
  отказ и тайм-аут реле без прямого fallback; настоящий локальный TLS Upgrade.
- Node.js: настоящий локальный TLS/WSS → TCP echo, двусторонние байты,
  фрагментация, ключ доступа, сертификат, capacity и тайм-ауты.
- Android: защищённое сохранение/восстановление URL и прежние обязательные тесты.
- **Не проверено:** развёрнутый внешний узел → Telegram и физическая мобильная
  сеть. Для подтверждения нужны оператор/страна, устройство, версия/commit APK,
  доступный узел и успешные сообщения/загрузка/повторное подключение.
