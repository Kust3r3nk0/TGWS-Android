# Smart Connection Update — поэтапный контракт

Только Android 16+ / API 36+. Существующие Premium Minimal, три вкладки,
настройки, Keystore, applicationId и локальный listener `127.0.0.1` сохраняются.
Физические испытания выполняет владелец; результаты обсуждаются в чате без
публикации устройства, оператора, токенов и адресов реле.

## 0.4.2 — Stability & Recovery

Рабочая ветка `feature/0.4.2-relay-stability`, [PR #26](https://github.com/Kust3r3nk0/TGWS-Android/pull/26).
Повторная Debug-сборка: versionName 0.4.2 / code 20, тег `v0.4.2+rev.2-debug`.
Исходный Debug-предрелиз code 19 сохраняется как отдельная сборка.

Реализованы исправления HTTP Upgrade/Close, ресурсов и восстановления на базе
RouteBackoff, раздельные причины отказа локального handshake, setup и сессий.
Новый общий setup deadline не расширяется числом кандидатов; TCP fallback получает
ограниченный резерв. BACKOFF одного endpoint не блокирует независимый разрешённый
маршрут. Паузы 1–30 с, endpoint Retry-After до 60 с и одиночная recovery probe
проверяются управляемыми часами; повторная передача MTProto-байтов отсутствует.

[Таблица первопричин, аудит всех девяти компонентов и обновление Worker](RELAY_STABILITY_0.4.2.md).
Worker сохраняет 6 сессий/isolate, 16 МиБ суммарно/сессию и границы очереди.
Без drain/подтверждённого flow control непрерывные большие передачи через него
не заявляются. Существующее [собственное WSS-реле](MOBILE_NETWORKS.md) использует
stream backpressure и остаётся альтернативой для крупных передач.

### Приёмка 0.4.2

Установить APK с совместимой подписью поверх прежнего, **не удаляя приложение**.
Обновить модуль существующего Worker, сохранив токен/домен. Убедиться, что порт,
MTProto secret, WSS URL, режим транспорта и оформление не изменились.

| Сценарий | Что проверить |
| --- | --- |
| Wi-Fi и мобильная сеть отдельно | Сообщения в обе стороны, отсутствие повторяющегося цикла подключения/обрыва |
| Wi-Fi → LTE и LTE → Wi-Fi | Старые сессии закрыты; новые используют текущую сеть, listener сохранён |
| Несколько start/stop и повторный запуск приложения | Сессии/попытки завершаются, порт освобождается, настройки сохранены |
| Основной Worker недоступен/занят | Диагностика различает HTTP/Close и backoff; в автоматическом режиме доступен разрешённый резерв |
| «Только реле» с недоступным реле | Контролируемый отказ без скрытого прямого подключения |
| SD/HD-фото, видео, кружки в обе стороны | Проверить фактическую доставку; различать BYTE_LIMIT Worker и неожиданный обрыв |
| Передача более 16 МиБ | Для Worker фиксировать ожидаемый лимит; полноценную крупную передачу проверять через совместимое собственное реле |
| Фон 30–60 минут и восстановление после отсутствия сети | Нет цикла зависания/переподключений, после восстановления новая сессия работает |
| Выключение прокси | Сессии и операции подключения закрыты, уведомление исчезло |

Для каждого сбоя передать в чат версию/code, режим, шаг/направление передачи,
итог и безопасный отчёт из диагностики: категория, HTTP/Close, причина завершения,
длительность/байты. Не присылать секреты и приватные URL. Успешный CI не является
подтверждением Telegram или внешнего Cloudflare на физическом устройстве.

## 0.5.0 — Smart Connection Update · запланировано

Начинать отдельную ветку/PR после проверки 0.4.2. Реализация этого этапа
в 0.4.2 не заявляется.

- Smart Routing: только разрешённые и совместимые с DC/media TCP/WSS/Worker/CF/
  собственное реле/HTTP2; автоматический, ручной и резервный режимы для новых сессий.
- Ограниченная статистика с затуханием: реальные setup/outcome/обрывы и время
  работы; один TCP handshake не подтверждает Telegram. Без агрессивного polling.
- Профили «Автоматический», Wi-Fi, мобильный и пользовательский: разрешения,
  приоритет/резерв, recovery и энергосбережение; без лишних SIM/сетевых идентификаторов.
- Health Monitor: DC, длительность, доля успешных попыток, обрывы, причины выбора;
  оценка качества обязана показывать «Недостаточно данных» при малом числе наблюдений.
- Live Traffic: реальные счётчики, ограниченная история/частота, отрисовка только
  видимого экрана; без фонового опроса ради анимации.
- Необязательные уведомления о длительном сбое/восстановлении, резерве и критической
  конфигурации с подавлением кратковременных повторов.

## 0.6.0 — Relay & Performance Update · запланировано

Отдельная ветка/PR после Smart Routing: управление несколькими зашифрованными
VPS-реле, основной/резерв, ручной/автоматический выбор и безопасное развёртывание
из `relay/`. SSH-управления из APK нет.

Media Optimizer учитывает media/DC, порядок байтов, частичные чтения, продвижение
обоих направлений и bounded backpressure; без replay, сжатия или изменения пакетов.
Foreground service работает через NetworkCallback, без постоянного прогрева,
необоснованных wake locks и неконтролируемых потоков. Quick Settings — только
после проверки ограничений FGS на API 36+.

## Общие gates

Unit/integration, Lint, Debug build, API 36/37, установка поверх предыдущей версии
с сохранением данных и серверные регрессии обязательны. Каждый этап имеет свои
проверяемые артефакты, source SHA, checksum, PR и ограничения.
Не возвращать Cloudflare DNS, не ослаблять TLS/авторизацию/DC allowlist, не
добавлять VPN/WebView/Zapret. Не объединять PR автоматически. Stable требует
доверенной Release-подписи и отдельной физической приёмки/одобрения владельца.
