# Собственное VPS-реле: установка и обновление

Требуется ваш VPS Linux/systemd, Node.js 22+ и npm, DNS-имя с доверенным TLS-сертификатом
для этого имени. Android использует только WSS/443 и проверяет сертификат/имя.
В APK нет SSH-клиента; Codex не подключается к вашему серверу и не меняет аккаунт.
Не публикуйте token, private key и URL вида `wss://domain/TOKEN/apiws`.

## Установка на сервере

1. Получите исходники нужного проверенного commit/tag в отдельный каталог на VPS.
   Запустите `npm --prefix relay ci --ignore-scripts` и `npm --prefix relay test`.
2. Убедитесь, что `/usr/bin/node` — Node 22+. Выполните от root `bash relay/deploy/install.sh`.
   Скрипт ставит код в `/opt/tgws-relay`, создаёт отдельного непривилегированного пользователя
   и unit. Он не запускает службу, не генерирует и не перезаписывает ваши ключи/токен.
3. Отредактируйте `/etc/tgws-relay/relay.env` по примеру `relay/deploy/relay.env.example`.
   Случайный token создаётся однократно на VPS командой `openssl rand -hex 32`.
   Сохраните его в файле, не в репозитории и не в командной строке systemd.
4. Установите доверенные `fullchain.pem`/`privkey.pem` по указанным путям.
   Каталог: root:tgws-relay / 0750; TLS-файлы: root:tgws-relay / 0640;
   `relay.env`: root:root / 0600. Отладочные localhost-сертификаты запрещены для deploy.
5. Откройте входящий TCP 443 в firewall VPS/панели хостера, сохраните SSH-доступ для
   администрирования. Разрешите исходящий TCP 443 только к allowlist DC из `relay/server.mjs`
   при использовании egress firewall; системный DNS и обновления сертификата учитывайте отдельно.
   Не открывайте произвольные внутренние порты и не выключайте firewall целиком.
6. Запустите `systemctl enable --now tgws-relay`. Проверьте `systemctl status tgws-relay`
   и `journalctl -u tgws-relay`: только общие сообщения, без URL/token/пакетов.
7. В Android добавьте `wss://ВАШ_ДОМЕН/ВАШ_TOKEN/apiws` в менеджер, выберите основной/резерв,
   явно включите менеджер и сохраните. Проверка Upgrade не является проверкой Telegram.

Служба использует отдельного пользователя, ограниченные capabilities, read-only filesystem,
защиту home/kernel, 256 МиБ RAM, TasksMax/NOFILE и 15-секундное окно остановки. Лимит
VPS по умолчанию 8 сессий; разрешённый диапазон 1–64. Это не меняет лимиты Cloudflare Worker.
Если сертификаты обновляются symlink-цепочкой из ACME-каталога, настройте deploy hook,
который копирует доверенные новые файлы с правами выше и перезапускает службу;
не делайте весь ACME/private-key каталог общедоступным.

## Обновление

Получите новый проверенный commit, выполните серверные тесты, повторите `install.sh`.
Он сохраняет `relay.env` и TLS-файлы. Затем `systemctl restart tgws-relay`.
Плановый restart закрывает текущие сессии; Telegram создаёт новые. Секрет MTProto,
старый token и Android-конфигурацию менять не требуется. При откате используйте
предыдущий проверенный код, сохранив те же внешние конфигурационные файлы.

Переменные: TGWS_MAX_SESSIONS 1–64; TGWS_CONNECT_MS 1000–15000;
TGWS_IDLE_MS 30000–3600000; TGWS_WRITE_MS 1000–30000. Выбирайте значения по измерениям,
не увеличивайте все тайм-ауты ради скрытия ошибок. TGWS_LISTEN_HOST допускает только
локальные bind-адреса `0.0.0.0`, `127.0.0.1`, `::`, `::1`; TGWS_LISTEN_PORT 1–65535,
но приложение подключается к публичному 443, при другом bind нужен безопасный TCP passthrough.

Реле принимает только точные DC/IP из Flowseal, защищённый token path, двоичные сообщения
и 64-байтовый init. Оно не является произвольным TCP-прокси. Лимиты сообщения/backpressure,
тайм-ауты и TLS нельзя отключать. Реальные HD/видео/фон проверяет владелец отдельно.
