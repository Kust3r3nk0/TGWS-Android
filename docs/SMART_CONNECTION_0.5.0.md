# TGWS-Android 0.5.0 — Smart Connection Update

Тестовое обновление Android 16+ / API 36+, versionCode 21. Новые функции включаются
явно; старые настройки, секрет, Keystore, transport mode и внешний вид сохраняются.
Это Debug Pre-release, не Production и не подтверждение устойчивости внешнего Telegram.

## Новые функции

- Smart Routing для новых сессий: автоматический выбор, ручной транспорт без скрытого
  fallback либо основной и разрешённые резервные транспорты.
- Четыре сохраняемых профиля: автоматический, Wi-Fi, мобильная сеть, пользовательский.
  Автовыбор учитывает только тип активной сети, без записи SIM/оператора/сетевых адресов.
- В каждом профиле: разрешённые транспорты, приоритет, резерв, адаптивное восстановление
  и энергосбережение. Настройки → Транспорт → Smart Connection; для изменения остановите прокси.
- Health Monitor: качество, попытки/отказы/обрывы, фактический setup time, причина выбора,
  DC/media и длительность активных сессий. При недостатке наблюдений показано отсутствие данных.
- Live Traffic: реальные скорости, итоговые байты, сессии и отметки сетевых сбросов/обрывов.
- Необязательные уведомления о длительном сбое, восстановлении, резервном транспорте
  и критической конфигурации. Включаются отдельно в настройках диагностики.

## Исправления

- Смена сети сначала закрывает старые сессии с причиной NETWORK_CHANGED, затем
  инвалидирует транспортную фабрику. Старые результаты не влияют на новый профиль.
- Одинаковый собственный endpoint и Worker не расходуют две попытки одной сессии
  и используют общий cooldown. Независимый разрешённый маршрут остаётся доступен.
- Счётчики сохраняют последние байты после остановки, график не продолжает показывать
  скорость последней работающей сессии. Переключение вкладок не меняет прокси.

## Оптимизация

Выбор пассивный: до 128 наблюдений за 10 минут, вес уменьшается вдвое за 2 минуты.
Ранжирование учитывает DC/media, реальные входящие байты, длительность, setup и
удалённые отказы. Один TCP/TLS/Upgrade не подтверждает Telegram или доставку сообщений.
Маршрут с предыдущим отказом получает контролируемую пробу при новом запросе не чаще
раза в минуту; энергосбережение — раз в 5 минут и без прогрева неиспользуемых WSS.
RouteBackoff, одиночная recovery probe, Retry-After и общий setup deadline остаются
обязательными. Выключение адаптивного backoff сохраняет минимальную защитную паузу.
Активные сессии не мигрируют и байты не переотправляются.

История трафика — максимум 60 точек в памяти, не чаще раза в секунду; длинные
паузы не превращаются в выдуманную скорость. Отрисовка останавливается вне видимого
экрана. Нет дополнительного сетевого polling. Уведомления: сбой от 30 секунд,
ограничение повторов 5 минут, восстановление только после входящих данных.

## Техническое

По умолчанию Smart Routing выключен: прежний пятистрочный формат транспортных
настроек остаётся побайтово совместимым. После явного изменения профили сохраняются
в том же зашифрованном transport record. Ключи и MTProto secret не заменяются.
DIRECT ограничен WSS/TCP, «Только реле» — собственным реле. В автоматическом
транспортном режиме Smart использует настроенные Worker/CF/собственное реле,
Direct WSS/TCP; пустая конфигурация CF допустима только при включённом Smart.
HTTP2 остаётся только для поддерживаемых media/DC при настроенном CF-домене.
Ручной несовместимый маршрут завершается ошибкой конфигурации без обхода разрешений.
Health quality требует минимум 5 наблюдений с входящими данными или отказом;
процент относится к этим наблюдениям, а не к доставленным сообщениям Telegram.
Диагностический JSON schema 3 дополнен enums/числами, без endpoint URL/токенов.

## Общее сведение

Протокол Worker в 0.5.0 не менялся: если уже установлен исправленный модуль 0.4.2,
повторный deploy не требуется. Старый Worker обновите по инструкции 0.4.2,
сохранив токен и домен. APK не развёртывает Worker автоматически.
Защита Worker прежняя: 6 сессий/isolate, 16 МиБ суммарно/сессию, очередь
4 МиБ + 4 Б / 64 сообщения. Для крупных медиа доступно совместимое собственное
реле из relay/; непрерывная передача больших файлов через Worker не обещается.
Стабильность мобильной сети, HD-фото/видео, фон и реальное восстановление проверяет
владелец. Multi-VPS Manager и Media Optimizer относятся к 0.6.0.

## Установка и проверка

1. Установите APK поверх совместимо подписанной версии, не удаляя приложение.
   При несовместимой подписи остановите установку. Сверьте версию 0.5.0/code 21,
   порт, секрет, реле и тему; не присылайте их в отчёт.
2. Сначала проверьте старый режим с выключенным Smart: сообщения, SD/HD-фото,
   видео и большие файлы в обе стороны; для Worker учитывайте лимит 16 МиБ.
3. Остановите прокси, включите Smart, настройте Wi-Fi/мобильный профиль. Проверьте
   AUTO, MANUAL и FAILOVER с недоступным основным и рабочим разрешённым резервом.
   MANUAL и «Только реле» не должны переходить на запрещённый прямой транспорт.
4. При смене Wi-Fi ↔ LTE проверьте новый профиль, закрытие старых сессий,
   восстановление Telegram без постоянного 30-секундного цикла. Работу listener
   не считайте подтверждением внешнего подключения.
5. Проверьте диагностику, реальные счётчики, отсутствие вымышленного ping,
   поворот Activity, повторное открытие и сохранение профилей. Выключение прокси
   должно закрыть соединения и обязательное уведомление.
6. Разрешите дополнительные уведомления по желанию: короткие обрывы не должны
   создавать спам. Проверьте фон 30–60 минут. В чат передайте версию, режим,
   сценарий/направление передачи, результат и безопасный JSON из диагностики.
   Личные данные, секреты, приватные URL и сведения об операторе не публикуйте.
