# 0.6.3 — Локальный DPI/SOCKS5 · Debug

Android 16+, code 25. Тестовый Pre-release, не гарантия обхода блокировок.

## Новые функции

В Настройки → Транспорт добавлен выключенный по умолчанию адаптер локального SOCKS5 на 127.0.0.1. Подходит для отдельно запущенного ByeDPI/совместимого SOCKS5-сервиса. В TGWS не встроен DPI-движок, другой APK или VpnService. Настройка стратегии обхода выполняется во внешнем сервисе.

Через адаптер идут исходящие TCP/WSS, Worker/собственные WSS-реле, проверки реле и автонастройка. SOCKS5 CONNECT поддерживает числовые IPv4/IPv6 назначения; DNS остаётся у активной Android-сети. Порт локального сервиса сохраняется отдельно от секретов, применяется сразу при остановленном прокси. Старые настройки и secret не заменяются.

## Безопасность

- Подключение только к 127.0.0.1, без SOCKS-аутентификации; режим внешнего сервиса должен быть совместим.
- Общий deadline охватывает DNS, локальное соединение и SOCKS handshake; отмена закрывает сокет.
- При отказе локального сервиса нет скрытого прямого подключения. TLS по-прежнему проверяет сертификат и исходное имя WSS-сервера.
- HTTP/2 media через этот адаптер не поддерживается и завершается ошибкой вместо прямого обхода настройки.
- MTProto listener остаётся на 127.0.0.1. Порты SOCKS и MTProto должны отличаться.

## Настройка на телефоне

1. Получить DPI-инструмент из его официального репозитория и запустить в режиме **локального прокси**, а не VPN-маршрутизации. Совместимость конкретного APK с Android 16 проверяется владельцем.
2. Указать в нём 127.0.0.1 и порт SOCKS5 (у ByeDPI документирован порт 1080 по умолчанию), выбрать/проверить его стратегию.
3. В TGWS остановить прокси → Настройки → Транспорт → указать тот же порт → включить «Направлять TCP/WSS через локальный SOCKS5».
4. Выполнить автонастройку, затем запустить TGWS и открыть Telegram. Проверить Wi-Fi и мобильную сеть отдельно, фон и крупные медиа. Оба приложения должны продолжать работать.
5. Для возврата к обычному подключению остановить TGWS и выключить адаптер.

## Что исследовано и что это не решает

По тайм-аутам Direct WSS/TCP нельзя установить, блокируется ли IP, SNI/DPI или отсутствует ответ сервера. Реле нужно проверять отдельно в явно настроенном режиме. Этот адаптер добавляет возможность применить внешний DPI-сервис; успешный локальный тест SOCKS не подтверждает обход у оператора.

ByeDPI изменяет обработку/разбиение начальных TCP/TLS данных. Он не заменяет адрес назначения внешним сервером. При недоступности самого IP могут потребоваться собственное доступное WSS/VPS-реле или другой доступный внешний транспорт. Простая подстановка cloudflare.com в SNI не создаёт реле и не заменяет TLS-проверку.

Уже поддерживаются собственные WSS/VPS-реле и Worker; их надо явно настроить. Worker сохраняет лимит 16 МиБ/сессию. Никакие чужие публичные прокси/токены не встроены. Другие локальные SOCKS5-сервисы можно исследовать отдельно; их сетевой выход и стратегия не управляются TGWS. Стороннее приложение само отвечает за выбор сети, поэтому при смене сети TGWS закрывает свои соединения, но не может управлять его lifecycle.

## Источники

- [ByeDPI, основное ядро](https://github.com/hufrea/byedpi): локальный SOCKS, параметры методов, MIT; не копировалось в APK.
- [ByeDPI Android](https://github.com/dovecoteescapee/ByeDPIAndroid#how-to-use-byedpi-with-adguard): официальный пример proxy-only + SOCKS5 127.0.0.1:1080; Android-оболочка GPL-3.0, не включена в TGWS.
- [ByeByeDPI](https://github.com/romanvht/ByeByeDPI): отдельный Android-проект, не встроен и не объявлен проверенным на устройстве.

Проверка сети и Telegram на физическом устройстве выполняется владельцем. Секреты, URL и личные данные в отчёты не включать.
