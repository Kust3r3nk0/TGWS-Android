# TGWS-16-017 — физическое тестирование владельцем

Приоритет P0. Требование владельца от 16.10.2026.
[English](en/PHYSICAL_TESTING.md) · [шаблон отчёта](OWNER_TEST_REPORT_TEMPLATE.md).

## Обязанности

**Codex:** разработка/оптимизация, unit/integration/CI, компиляция/Lint, подготовка Debug APK,
ссылка на конкретный Actions run/artifact, версия и commit SHA, checksum/changelog/ограничения,
анализ результатов владельца, исправления и повторные автоматические проверки.

**Владелец:** установка на личные телефоны, Telegram MTProxy E2E, задержка/стабильность,
Wi-Fi/мобильный интернет, SNI/Fake TLS/Cloudflare, One UI 8.5/9.0, Live Updates/Quick Settings
(если реализованы), WebView Stable/Beta и обратная связь. Неподдерживаемые возможности
помечаются «не поддерживается», а не «пройдено».

Codex не ищет/подключает личные смартфоны, не просит ADB/доступ к ним и не обязан сам
выполнять физическую проверку. Автоматическая матрица использует CI-эмуляторы.
Ожидание телефона/ручного результата не блокирует разрешённый debug-предрелиз после gates.
Публикация APK не означает физическое подтверждение и не превращает alpha в стабильный релиз.

## Рабочий цикл

1. Codex завершает проверяемую группу изменений и автоматические тесты.
2. Успешный Android CI публикует APK ZIP с `build-info.json`, `SHA256SUMS`, changelog и
   `OWNER_HANDOFF.md`. Последний содержит точную версию, source SHA, SHA проверенного tree,
   ссылку на run и шаблон результатов. При PR source SHA и merge/tree SHA могут отличаться.
3. Для обновления поверх прежней установки предпочтителен проверенный GitHub Debug Pre-release
   с прежним сертификатом: случайный CI debug-ключ может отличаться. Не удалять настройки
   автоматически ради несовпавшей подписи. Ключ подписи не входит в CI-артефакты.
4. Владелец устанавливает подходящую сборку, выполняет сценарии и заполняет отчёт.
5. Codex разбирает воспроизводимый дефект, добавляет соответствующую проверку/исправление,
   повторяет gates и публикует следующую тестовую сборку.
6. Для неясной/зависящей от окружения ошибки фиксируется открытая проблема и нужные сведения;
   компиляция или скрытие исключения не считаются исправлением. Версия One UI/WebView и
   ограничения устройства указываются явно. Исторические отчёты не переписываются как новые проверки.

## Проверка с телефона, без компьютера

Откройте ссылку Actions из сообщения о сборке, выберите успешный run → **Artifacts** →
`TGWS-Android-<version>-debug-<SHA>`. Скачайте ZIP, распакуйте файловым менеджером;
версия/commit/run записаны в `OWNER_HANDOFF.md` и `build-info.json`.
Проверенный APK с сохранённой подписью также публикуется в разрешённом Debug Pre-release.

Модель/производитель, Android и One UI: настройки телефона → сведения об устройстве/ПО.
Выбранный WebView: параметры разработчика → реализация WebView; версия пакета — сведения
о соответствующем приложении. Расположение пунктов зависит от OEM. Не меняйте провайдера
без понимания последствий; Dev/Canary не обязательны. WebView в текущем TGWS не используется:
renderer/page тесты неприменимы. Версию провайдера нужно уточнять при связанной с его обновлением проблеме, а не требовать переключения каналов для проверки нативных функций.

Шаблон можно заполнить прямо в новом GitHub Issue «Отчёт физического тестирования».
Для обратной связи достаточно версии/commit, среды, шагов и фактического результата.
Не публиковать MTProto secret, relay URL/ключи, содержимое сообщений, SIM/IMEI/serial,
полные конфигурации и сырые пользовательские логи. Разрешённый обезличенный экспорт
диагностики сначала просмотреть вручную.

## Статусы

Каждый сценарий: **не проверено / пройдено / ошибка / не поддерживается / неприменимо**.
Автор подтверждения физических результатов — владелец. [Ответ для 0.3.6 получен](OWNER_VALIDATION_0.3.6.md): частично пройдено, есть конкретные сбои. Статус ведётся отдельно для версии и сценария; общий ярлык об отсутствии проверки после ответа не используется. Непроверенная следующая сборка не наследует статус «пройдено» автоматически.

Окончательный стабильный release gate дополнительно требует всех критериев исходного ТЗ
и доверенной production-подписи. Debug APK можно подготовить раньше, с честным статусом.
