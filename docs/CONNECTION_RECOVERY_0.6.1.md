# 0.6.1 — Connection Recovery

Android 16+ / API 36+, code 23. Исправление на базе опубликованного 0.6.0
и актуального main. Это тестовый Debug Pre-release, не Production.

## Воспроизведённые причины

1. В автоматическом Smart-профиле при холодном старте прямые WSS-маршруты
   могут оказаться перед настроенным Worker/реле. Для media DC есть два имени.
   Две зависшие попытки по 8 секунд и резерв TCP почти исчерпывали общий
   25-секундный setup deadline: исправное реле получало около секунды.
2. Четыре неудачных Cloudflare-кандидата могли исчерпать лимит попыток,
   исключив настроенный Worker из этой сессии даже при быстрых отказах.

Оба сценария воспроизведены регрессионными тестами с управляемыми отказами;
до исправления тесты падают. Это не подтверждает причину каждого реального
сетевого отказа без безопасной диагностики соответствующей сессии.

## Исправление

Пробные WSS/CF/HTTP2-маршруты оставляют одну из существующих четырёх попыток
и время для последующего разрешённого настроенного Worker или собственного
WSS-реле. Резерв TCP сохраняется. Общий deadline и лимиты не увеличены.
Маршрут в известном cooldown не резервирует ресурсы; backoff и Retry-After
сохраняются. MANUAL и «Только реле» не получают скрытых альтернатив.
Установленные MTProto-сессии не переносятся, байты не повторяются.

UI, secret, Keystore, зашифрованные настройки, DNS активной Android-сети и
проверки TLS не изменены. APK не обновляет сервер. Worker и Node-реле не
менялись относительно 0.6.0; для этого исправления redeploy не нужен.
Worker по-прежнему ограничен 16 МиБ/сессию.

## Проверка обновления

1. Установить 0.6.1 Debug поверх совместимой подписанной сборки, не удаляя
   приложение. Проверить сохранение настроек и секрета; не публиковать их.
2. Остановить и запустить прокси. Проверить сообщение Telegram и повторить
   запуск после закрытия приложения, чтобы проверить холодный выбор маршрута.
3. В автоматическом режиме с настроенным Worker/реле проверить соединение
   в сети с недоступными прямыми маршрутами. Отдельно проверить media DC.
4. Проверить MANUAL, «Только реле», смену Wi-Fi/мобильной сети и остановку.
5. При сохранении проблемы сообщить версию, режим, состояние локального
   сервера и обезличенную диагностику из приложения. Не отправлять URL/токены
   реле, Telegram-ссылку, secret, адреса или личные данные.

Проверка Telegram/HD-медиа и продолжительной работы на физическом устройстве
выполняется владельцем. Исправление не снимает внешние блокировки и лимиты Worker.
