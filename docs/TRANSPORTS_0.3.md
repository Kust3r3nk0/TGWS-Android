# Транспорты 0.3.0-alpha

[English](en/TRANSPORTS_0.3.md). Android 16+. [ТЗ](TZ_0.3.0-alpha.md).
Реализация проверяется локальными автоматическими тестами. **Проверка владельцем на физическом устройстве: ожидается.**

## Выбор режима

Остановите прокси перед изменением конфигурации. При обновлении с 0.2 порт, секрет,
URL и прежний direct/relay-only режим сохраняются. Новые параметры хранятся в отдельной
AES-256-GCM записи Android Keystore; ошибка расшифрования требует явного восстановления.

| Режим | Маршруты |
|---|---|
| Прямой | Прежний WSS Telegram → TCP. Блокировка IP может затронуть оба пути. |
| Только реле | Только заданный собственный Worker-совместимый WSS endpoint. Прямой fallback запрещён. |
| Автоматический Cloudflare | Настроенные Worker → совместимый Cloudflare Proxy → прямой TCP. Выбирайте relay-only, если прямые соединения нежелательны. |

CF Proxy, Cloudflare Worker и собственное реле требуют разных серверных конфигураций.
Домен сам по себе не создаёт узел. Встроенных чужих аккаунтов/рабочих endpoint нет.

В разделе расширенных транспортов укажите до **8 базовых CF-доменов** и/или **8 Worker URL**,
по одному на строку. Базовый домен задаётся без схемы/пути/порта; узел будет
`kws2.<base>`, `kws4.<base>` и т. п., WSS path `/apiws`.
Worker URL имеет вид `wss://<ваш-worker>.<ваша-зона>.workers.dev/<ключ>/apiws`.
Приложение добавляет `?dst=<закреплённый-IP-DC>&dc=<DC>` к указанному пути;
для нашего Worker путь должен содержать `<ключ>/apiws`, query вручную не задаётся. URL скрыт, его нельзя публиковать.
Сохранённый URL собственного реле добавляется в список Workers только явной кнопкой.

Пример структуры (заменить своими совместимыми узлами; адреса ниже не работают):

```text
Режим: Автоматический Cloudflare
CF domains: proxy.example
Worker URLs: wss://worker.example/<ключ>/apiws
HTTP/2 media: включать только для поддерживающего /api сервера
```

До передачи пользовательских пакетов выбираются максимум два Worker и два CF-домена,
не более **четырёх non-TCP попыток + TCP**, по 8 с на попытку и общему setup-бюджету 40 с.
HTTP/2 и WSS на одном домене считаются отдельными попытками. Отказанные маршруты
ротируются, backoff 1–30 с. Передаётся только свежий relay init; пользовательские пакеты
не переигрываются. Во время сессии маршрут не меняется. После разрыва Telegram создаёт новую.

Списки редактируются явно и целиком проверяются до сохранения. Автоматической загрузки
списков из интернета в этой версии нет; не существует скрытого источника обновлений.

## Fake TLS и ссылки

Начиная с 0.3.9 включённый Fake TLS также принимает обычный Obfuscated2 с тем же секретом. Оба формата проходят криптографическую проверку; удалённые TLS-сертификаты проверяются независимо.


Необязательный домен Fake TLS включает локальный ClientHello/HMAC/ServerHello и record
camouflage по Flowseal v1.11.2. Telegram-ссылка использует `ee` + 32 HEX secret + HEX домена.
Без домена ссылка использует `dd`. Импорт поддерживает 32 HEX, `dd`, `ee` и локальные
`tg://proxy` / `https://t.me/proxy` ссылки с сервером `127.0.0.1`.

Fake TLS относится к **Telegram → локальный listener**, а удалённые WSS/H2 выполняют
настоящую проверку сертификата, имени и TLS. Это не произвольный SNI fronting и не
гарантия обхода IP-фильтра. Неверный local ClientHello закрывается без dial к домену:
upstream camouflage-forwarding для посторонних клиентов намеренно не предоставляется на loopback.

## HTTP/2 media

Только в Auto CF с заданным CF-доменом и media DC: `HEAD https://kwsN.<base>/api`,
реальный ALPN `h2`, затем `POST /api` с телами MTProto-пакетов по upstream `cf_h2.py`.
Ответ HEAD допустим 2xx/405/501, HTTP/1.1 отклоняется. Произвольный Telegram DC и
обычный WSS Worker не объявляются HTTP/2 endpoint. До начала payload допустим fallback
на CF WSS/следующий разрешённый путь. После payload RST/GOAWAY/IO закрывает сессию без retry/replay.

Два незавершённых запроса на native-сессию, суммарно до 4 MiB тел запросов, один
буферизуемый ответ до 4 MiB, общий dispatcher 8 запросов. HTTP/2 flow control обслуживает
OkHttp, очередь запросов ограничена; cancel пробуждает ожидающих. HTML, недопустимые длины,
неверный TLS/ALPN и слишком большие ответы отклоняются. Активные native-сессии имеют
независимые CTR-состояния, их максимум 8. Байты диагностики — данные со стороны Telegram,
без TLS/HTTP overhead; setup/phase timings не являются Telegram ping.

## Сеть, диагностика и серверы

DNS и сокеты привязаны к одному активному Android `Network`, с ограничением времени/числа
адресов. IPv6-only работает при совместимых AAAA, системных DNS64/NAT64/464XLAT;
адреса IPv6 не выдумываются. Нет доступного маршрута — предсказуемая ошибка.
Смена default network/DNS/link закрывает старые запросы, сессии и пул. Новые сессии
создаются заново; бесшовная миграция не заявляется. Captive portal/неподтверждённый
internet видны отдельно; отсутствие Android validation само по себе не доказывает отказ CF.

«Диагностика» показывает listener, сеть, PLMN/data-SIM при доступности, семейства адресов,
DNS/Private DNS/NAT64, полученные A/AAAA (до 8 адресов, только локально),
маршруты/DC/media/этап/ошибку/время/попытки и счётчики. При переиспользовании
H2-соединения новые DNS/TCP/TLS фазы и ответы не выдумываются — «неизвестно».
Явная проверка не чаще раза в 30 с открывает максимум три транспортных handshake,
без MTProto-пакетов. Обезличенный экспорт сначала показывает предпросмотр, затем
копируется по кнопке; в нём нет URL, доменов, IP, DNS, PLMN, SIM-идентификаторов и секретов.
Обычное `READ_BASIC_PHONE_STATE` используется только для необязательной radio-диагностики;
опасные телефонные разрешения не запрашиваются. Недоступные данные — «неизвестно».

- [Собственное WSS-реле](MOBILE_NETWORKS.md): фиксированные DC, path key, локальные TLS/TCP тесты.
- [Worker без компьютера](../cloudflare-worker/README.md): отдельный компонент, текущий лимит
  **16 MiB на сессию**; большие загрузки могут прерываться. Новый клиент H2 этот лимит не снимает.
- CF Proxy требует собственного уже совместимого с Flowseal `kwsN.<base>/apiws` и `/api`
  сервера. Настройка произвольного Cloudflare hostname недостаточна; универсальный CF deploy не включён.
- [Операторы и физическая матрица](RU_MOBILE_OPERATORS.md). Внешние транспорты,
  мобильный доступ и длительный screen-off E2E ожидают проверки владельцем.
