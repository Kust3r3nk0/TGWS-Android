# Codex + GitHub Actions: разработка TGWS-Android по ТЗ

Это инструкция по запуску **одной задачи Codex**, после которой GitHub Actions самостоятельно проверяет изменения и при успешных проверках предоставляет Debug APK.

> Codex пишет код и запускает доступные инструменты; GitHub Actions **только** проверяет и собирает результат. Добавление Issue или ТЗ в репозиторий само по себе не запускает Codex. Для разработки необходим запущенный агент с доступом к репозиторию.

## 1. Подготовка

1. Откройте проект `Kust3r3nk0/TGWS-Android` в Codex Cloud или локально в Codex CLI/IDE.
2. Убедитесь, что у агента есть разрешённый доступ к репозиторию. Для локальной сборки нужны JDK 17, Android SDK и Gradle Wrapper из репозитория.
3. Для обычной реализации попробуйте **GPT-6.1 Sol, средний уровень рассуждения, обычная скорость**. Для сложной сетевой архитектуры и трудно воспроизводимых ошибок повышайте уровень после оценки результатов.
4. Работайте в отдельной ветке. Файл [AGENTS.md](../AGENTS.md) содержит постоянные правила проекта.

## 2. Готовый запрос вместе с ТЗ

```text
Выполни приложенное ТЗ для TGWS-Android за один максимально самостоятельный проход.
Следуй AGENTS.md и существующей архитектуре проекта.
Начни реализацию после краткой проверки релевантных файлов; не трать квоту на повторный анализ всего репозитория.
Выполняй доступные действия без промежуточных остановок, если они разрешены средой.
Добавь необходимые тесты, исправь ошибки и выполни:
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
Оформи результат отдельной веткой и PR, если это доступно.
Публикуй разрешённые debug-артефакты/предрелизы после автоматических gates, не объединяй PR в main.
Физические проверки выполняет владелец: не ищи личные телефоны/ADB и не заявляй неподтверждённые результаты.
В конце сообщи: реализованные пункты ТЗ, реальные результаты проверок, путь к APK/CI, оставшиеся проблемы.
[Ниже вставь ТЗ]
```

Пятичасовое окно лимита Codex — это **не гарантия пяти часов непрерывного выполнения**. Длительная работа может закончиться раньше из-за квоты, ошибок среды или необходимости одобрения действия. Инструкции повышают воспроизводимость, но не гарантируют выполнения любого ТЗ за один запуск.

## 3. Проверка изменений через GitHub Actions

У репозитория уже есть workflow [Android CI](../.github/workflows/android-ci.yml). Он запускается при PR в `main`, push в `main` и вручную (workflow_dispatch).

При успешной проверке workflow выполняет JVM-тесты, Android Lint, собирает `:app:assembleDebug` и загружает артефакт **`TGWS-Android-<version>-debug-<SHA>`**.

Как получить APK:

1. Создайте PR с изменениями Codex и дождитесь завершения Android CI.
2. Откройте страницу [Actions](https://github.com/Kust3r3nk0/TGWS-Android/actions/workflows/android-ci.yml).
3. Выберите запуск, соответствующий коммиту или PR, и проверьте статус.
4. Внизу страницы откройте **Artifacts** → `TGWS-Android-<version>-debug-<SHA>`, скачайте ZIP, распакуйте его.
5. Внутри будет Debug APK, если сборка и загрузка артефакта прошли успешно.

Debug APK предназначен для тестов и **не является стабильным подписанным релизом**. Успех CI не подтверждает реальные MTProto/WebSocket подключения. Для этого нужны отдельные интеграционные и Android E2E-тесты.

## 4. При сбое

- Проблема компиляции/теста/Lint: передайте Codex ссылку на упавший запуск и соответствующий лог, попросите исправить причину в той же рабочей ветке.
- Сбой окружения (SDK, доступ к сети): отделяйте его от ошибок кода и не заменяйте проверку ложным результатом.
- Закончилась квота: продолжайте по сохранённым коммитам и оставшимся пунктам ТЗ после восстановления доступа.
- Полностью автономный запуск без действия пользователя требует отдельно настроенного запуска агента и соответствующих разрешений; текущий workflow не запускает LLM самостоятельно.
