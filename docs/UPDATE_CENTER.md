# TGWS Update Center

Начиная с кандидата 0.4.0 центр использует общую графитово-синюю палитру Premium Minimal. Repository/Worker/Installer и формат категорий сохранены. Канал Stable выбран по умолчанию. [Release-подпись и миграция](RELEASE_0.4.0.md).


[English](en/UPDATE_CENTER.md). Android 16+, нативный Compose / Material 3. Вход: **Настройки → Обновления приложения**.

Центр показывает опубликованные GitHub Releases, реальную версию и примечания к релизу. Коммиты и ссылки из текста релиза не используются как источник APK. Без подходящей более новой версии отображается отдельное состояние актуальности.

## Проверка и расписание

- По умолчанию выбран **стабильный** канал. Нажмите строку «Канал обновлений» в информационной карточке, чтобы явно выбрать **Предварительный (Alpha / Debug)**. Подпись APK должна оставаться совместимой с установленным приложением в любом канале.
- Автоматические проверки включены, период по умолчанию — 6 часов. Доступны 15 минут, 1/3/6/12 часов, сутки и неделя.
- Используется одна уникальная периодическая задача WorkManager. Выключение отменяет её; изменение интервала обновляет её. Android выполняет работу приблизительно, с учётом Doze, сети и системных ограничений.
- Уведомления независимы от расписания. Отсутствие разрешения или блокировка канала не мешают самой проверке. Один релиз не уведомляется повторно.
- «Только Wi-Fi» относится к APK; проверка версий доступна через мобильную сеть. Учитывается активный Android Network, а не наличие посторонней Wi-Fi-сети. Смешанный VPN Wi-Fi/Cellular не считается подтверждённым Wi-Fi-only; VPN не обходится.
- Ручная проверка работает и при выключенном расписании. Между запросами выдерживается минимум 60 секунд; HTTP 403/429 и Retry-After откладывают следующую попытку. История и успешный результат сохраняются.

## Формат релиза

В Release Assets необходимы APK, `SHA256SUMS` и **`update-manifest.json`**:

```json
{
  "schema": 1,
  "package_name": "io.github.kust3r3nk0.tgwsandroid",
  "version_name": "0.3.10-alpha",
  "version_code": 16,
  "min_sdk": 36,
  "channel": "PREVIEW",
  "apk": "TGWS-Android-0.3.10-debug.apk"
}
```

`channel`: `STABLE` либо `PREVIEW`. Stable не допускает prerelease, Alpha и Debug. Числовой `version_code` должен быть выше установленного; SemVer также должен быть новее. `min_sdk` должен совпадать с APK и подходить текущей ОС. Имя APK разрешается только через assets того же релиза в официальном репозитории.

Манифест формируется из реальных параметров Gradle:

```bash
python3 .github/scripts/create_update_manifest.py \
  --apk-name TGWS-Android-0.3.10-debug.apk --channel PREVIEW \
  --output update-manifest.json
```

Debug publisher создаёт этот файл автоматически и включает его в `SHA256SUMS`. Старые релизы без манифеста не предлагаются автоматически: отсутствие versionCode не заменяется догадкой по тегу. Просматриваются до 100 опубликованных записей и до 8 новых кандидатов за проверку.

## Категории Release Notes

Используйте точные заголовки второго уровня. Категории без текста не показываются. Разрешены RU/EN пары:

| Русский | English |
|---|---|
| `## Важное` | `## Important` |
| `## Новые функции` | `## Features` |
| `## Исправления` | `## Fixes` |
| `## Оптимизация` | `## Performance` |
| `## Техническое` | `## Technical` |
| `## Общее сведение` | `## General` |

Текст без известного заголовка показывается в общей категории. Поиск слов «исправлено»/«добавлено» не используется. Длинные карточки раскрываются. Markdown отображается как текст; ссылки не запускают установку и не меняют источник файла.

## Загрузка и установка

1. Выберите подходящий канал и выполните проверку.
2. Нажмите «Обновить». Доступны реальный прогресс, отмена и повторная попытка. Загрузка связана с одной активной сетью; её потеря не переносит APK незаметно на другую сеть.
3. Проверяются размер и SHA-256 из `SHA256SUMS`. Затем библиотека Android `apksig` проверяет криптографическую подпись всего APK.
4. Проверяются package name, фактические versionName/versionCode/minSdk, текущий сертификат либо проверенная прямая ротация v3 с правом использования установленных данных. Чужая подпись и повреждённый APK отклоняются.
5. Только после этого запрашивается разрешение установки из этого источника, если оно нужно. После возврата нажмите «Продолжить установку». Системный установщик требует подтверждения.

Файл передаётся узким FileProvider только на чтение. Приложение не удаляется, скрытой установки нет. После восстановления процесса сохранённый файл проверяется снова; установка сама не запускается. При несовместимом сертификате смена канала не ослабляет проверку и не предлагает очистку данных.

Настройки Update Center хранятся отдельно. MTProto secret, Keystore, реле, транспорты и оформление не переписываются. Автоматизированная проверка `install -r` контролирует их сохранение вместе с настройками обновлений.

## Проверка владельцем

Установите Debug APK поверх предыдущего с совместимой подписью. Проверьте оба экрана, темы, выбранный интервал после перезапуска и ручную проверку при выключенном расписании. Для доступного более нового подписанного релиза проверьте отмену/повтор загрузки, Wi-Fi-only, системное разрешение и подтверждение установки. После установки убедитесь, что прокси использует прежний секрет и параметры. Отзывы и личные сведения о телефоне остаются в чате.

One UI и фактические задержки WorkManager зависят от прошивки и системных ограничений. Автоматические снимки создаются на эмуляторах API 36/37; сценарий доступного обновления в Compose-тесте использует детерминированный fixture, а не объявляет вымышленный публичный релиз. MTProto не зависит от WebView; новые зависимости WebKit не добавляются.
