# Сети 0.3.4: DNS, мобильные операторы и Wi-Fi

[English](en/NETWORK_COMPATIBILITY_0.3.4.md). Исследование 16 октября 2026.

Мобильные сети и Wi-Fi могут ограничивать доступность маршрутов. Один DNS или SNI не гарантирует соединение; требуется установить этап отказа.

## Что меняется в клиенте

- Только DNS активного Android Network, включая системный Private DNS и сетевые DNS64-ответы.
  Встроенные адреса 1.1.1.1/1.0.0.1 и DoH-клиент исключены из приложения. Android DNS не меняется.
- TCP: сохраняется предпочтение ОС, семейства чередуются до ограничения в восемь адресов;
  второй dial стартует через 250 мс. Две попытки одновременно на соединение, общий deadline,
  максимум восемь dial-потоков/32 queued tasks. Победитель продолжает обычный TLS с проверкой
  сертификата/имени, остальные сокеты закрываются. MTProto init/пакеты не рассылаются дублями.
- Смена сети отменяет старые DNS/dial/HTTP, закрывает сессии и сбрасывает backoff; Telegram
  создаёт новые. Бесшовного переноса активного соединения нет.
- Отказы native TCP/маршрута и deadline отделены от ошибки HTTP Upgrade; DNS/TLS остаются
  отдельными категориями. В обезличенном отчёте нет private URL, ключей, IP/DNS или пакетов.

## Причины и возможные действия

| Наблюдение/причина | Действие и граница |
|---|---|
| Недоступен встроенный Cloudflare DNS | В 0.3.4 он удалён. Системный resolver не зависит от выбора DNS старой версии приложения. |
| Системный Private DNS недоступен или фильтрует имя | Проверить его в Android; приложение не переопределяет системную политику. DNS-ошибка сама по себе не доказывает цензуру. |
| IPv6 blackhole при рабочем IPv4 или наоборот | Ограниченный параллельный TCP выбор сокращает ожидание. Обе недоступные семьи не становятся доступными. |
| IPv6-only/DNS64/NAT64 | Использовать сетевые DNS64-ответы для домена реле. Не подставлять чужой NAT64 prefix. Числовые Telegram DC требуют IPv4/CLAT; полная IPv6-only совместимость не подтверждена. |
| Блокировка прямых IP Telegram | Доступное **собственное или доверенное** WSS-реле на 443: существующий `relay/` работает независимо от Cloudflare; нужен внешний узел/сертификат. Локальный порт 1443/8443 удалённый путь не меняет. |
| Недоступны workers.dev или Cloudflare edge | Собственный доступный домен/Worker custom domain может помочь только при фильтрации имени, но не общего edge IP. При блокировке edge нужен доступный origin/другая инфраструктура. Чужие публичные реле автоматически не подбираются. |
| WSS Upgrade фильтруется, обычный HTTPS доступен | Уже имеющийся H2 `/api` работает **для media** и только на совместимом настроенном сервере. Полный H2 control-транспорт отсутствует; переключатель не обещает замену WSS для всех сессий. |
| Фильтрация SNI | Нужен доступный реальный домен с корректным сертификатом/сервером. `cloudflare.com` как произвольный SNI не создаёт маршрут и не скрывает целевой IP. Fake TLS в приложении защищает локальный Telegram→TGWS transport, а не автоматически удалённый TGWS→реле. |
| ECH | Перспективное отдельное развитие TLS-клиента/сервера и HTTPS DNS records; текущий SSLSocket/клиент его не реализует. Нельзя заменить ECH одной строкой SNI или включением WebView. ECH также не скрывает IP. |
| Captive portal, отсутствует интернет/ограниченный список сайтов | Выполнить вход в Wi-Fi средствами Android. При allowlist нужен разрешённый/доступный внешний endpoint; приложение не может гарантированно восстановить отсутствующую связность. |
| Worker обрывает крупную загрузку | Текущий шаблон ограничивает сессию 16 MiB; это не DNS-ошибка. Для длительного трафика использовать собственное реле с backpressure; Worker flow control — отдельная задача. |
| TLS interception, неверное имя/сертификат | Исправить сертификат/настройку своего сервера или сеть. Проверка TLS не отключается. |

Cloudflare DNS и Cloudflare Worker/Proxy — разные компоненты. Настроенные Worker/Proxy/H2
и зашифрованные адреса сохранены. Ни одна схема не гарантирует работу при любых блокировках.
Внешний узел автоматически не разворачивается: у проекта нет настроенной инфраструктуры
в доступной среде; публикация APK не создаёт новый доступный endpoint.

## Проверка владельцем без компьютера

1. Установить проверенный Debug APK 0.3.4 с прежним сертификатом; не удалять приложение ради
   смены подписи, чтобы не потерять Keystore. Для обновления использовать Debug Pre-release.
2. Проверить прежние порт/секрет/реле. DNS приложения теперь системный; генерация нового
   MTProto secret или ключа Worker для этого обновления не требуется.
3. Выключить Wi-Fi, запустить прокси, открыть «Диагностика» → «Проверить маршруты».
   Повторить на проблемном Wi-Fi. Ручной probe имеет предел частоты и не подтверждает Telegram E2E.
4. Для «Только реле» нужен совместимый **доступный** endpoint; обычный сайт не WSS-реле.
   В автоматическом режиме используются только уже настроенные Worker/CF-узлы.
5. Записать категорию DNS/TCP/TLS/handshake/deadline, сеть/оператора/дату, версию+SHA APK.
   Проверить текст туда/обратно, загрузку и 15–30 минут с выключенным экраном; каждый результат
   отдельно. Не публиковать полную конфигурацию, URL, секрет, SIM/IMEI или сообщения.
6. Передать [Проверки для разработчиков](TESTING.md). Доступность origin/Worker,
   Android/One UI/WebView и мобильные ограничения подтверждаются только фактическим тестом.

## Первичные источники и границы исследования

Использованы Firecrawl (поиск/чтение первичных источников), GitHub (код/CI) и runtime-проверка
доступной среды. Перебор нерелевантных подключений не даёт доступа к сетям оператора.
Это разбор основных классов отказов, не исчерпывающее доказательство причин в конкретной сети.

- [Android DnsResolver](https://developer.android.com/reference/android/net/DnsResolver): запросы
  конкретного Network, A/AAAA и RFC6724 sorting, CancellationSignal.
- [Android Network](https://developer.android.com/reference/android/net/Network): DNS и sockets
  одной сети; не process-wide VPN.
- [RFC 8305](https://www.rfc-editor.org/rfc/rfc8305): чередование семейства, рекомендуемый шаг
  250 мс, отмена проигравших; реализован TCP-этап, не весь DNS discovery engine RFC.
- [Google DNS64](https://developers.google.com/speed/public-dns/docs/dns64): синтез зависит от
  доступного NAT64 gateway; публичный DNS64 с чужим prefix не универсален. Google DNS не добавлен.
- [Cloudflare Workers TCP](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/):
  ограничения исходящих IP/портов и ошибки узла; это отдельный путь от DNS телефона.
- [Cloudflare ECH](https://developers.cloudflare.com/ssl/edge-certificates/ech/): требуется
  настоящий ECH с inner/outer ClientHello и поддержкой конфигурации; не обычная подмена SNI.
