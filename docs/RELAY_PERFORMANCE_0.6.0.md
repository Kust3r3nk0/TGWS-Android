# 0.6.0 — Relay & Performance Update

Android 16+ / API 36+, versionName 0.6.0, code 22. Тестовый Debug Pre-release;
реальная устойчивость Telegram/HD-медиа подтверждается владельцем, не компиляцией.

## Менеджер собственных реле

Настройки → Транспорт → Менеджер VPS-реле. Остановите прокси для изменений.
Добавьте до 8 совместимых собственных WSS-узлов, задайте названия и уникальные URL.
По умолчанию адреса скрыты; раскрытие включает FLAG_SECURE, уход с экрана скрывает их.
Черновик переживает поворот только в ViewModel; открытые URL не пишутся в saved state.
Нажмите «Применить к списку», затем «Сохранить настройки» в верхней карточке.
Включение менеджера — отдельное явное действие. Старый одиночный URL сохраняется,
а выключение менеджера возвращает прежнюю конфигурацию. Секрет и ключи не заменяются.

Выберите основной узел и разрешённые резервные:

- Ручной — только основной узел; отказ не открывает другой узел или прямой TCP.
- Основной → резерв — последовательный выбор по разрешённому списку.
- Автоматический — те же выбранные узлы ранжируются по пассивным данным Smart Routing.
  Учитываются DC/media, входящие байты, setup, продолжительность и удалённые отказы.

Менеджер применяется в «Только реле» и автоматическом транспортном режиме.
Прямой режим остаётся WSS/TCP. Разрешения профиля Smart всегда обязательны;
его MANUAL/FAILOVER не обходятся. Общий setup deadline, RouteBackoff и endpoint
Retry-After сохранены. В автоматическом режиме максимум 4 фактические non-TCP
попытки в одном setup; хранение 8 узлов не обещает проверку всех до deadline.
Одинаковый own/Worker endpoint не получает второй dial или обход cooldown.
Выбор применяется только к новым сессиям: активные MTProto-байты не мигрируют и не replay.

Каждый узел можно проверить вручную без запуска listener. Проверка TLS/WSS ограничена
по времени, не передаёт MTProto и не подтверждает Telegram. Один запрос одновременно,
повтор одного узла — не чаще раза/30 секунд. Уход с экрана, фон, редактирование узла
или смена сети отменяет запрос и закрывает сокеты. Показаны фактическое время,
безопасная категория отказа и HTTP Upgrade. Постоянных фоновых проверок нет.
В диагностике доступны активные сессии и номер собственного узла; имена, URL и токены
не экспортируются. Уведомление о резерве различает узлы одного WSS-транспорта.

## Media и VPS-реле

Параметр «Разрешить media DC» исключает несовместимый узел из media-маршрутов.
Опция предпочтения собственного реле для media выключена по умолчанию; она влияет
только на новые media-сессии при разрешённом автоматическом выборе. Размер файла
из зашифрованного потока заранее неизвестен. MTProto-пакеты не сжимаются и не меняются.

Node.js-реле теперь обновляет stall deadline после каждой записи до 16 КиБ,
а не по завершении целого сообщения до 4 МиБ. Backpressure и ограничение сообщений
сохранены. Закрывающаяся сессия занимает слот до подтверждения native TCP/WS/client
close; shutdown закрывает также сокеты до Upgrade и незавершённый TLS.
В локальных тестах VPS bridge передаёт по 20 МиБ в обе стороны; отдельный Kotlin
MTProto/TLS/WSS тест сверяет 24 МиБ в каждую сторону по независимому CTR-клиенту.
Это локальные автоматические проверки, не отчёт о реальном Telegram.

Worker не изменён: 6 сессий/isolate, 16 МиБ суммарно/сессию, очередь 4 МиБ + 4 Б /
64 сообщения. APK не снимает этот лимит и не обновляет внешний сервер сам.
Для крупных передач настройте совместимое собственное VPS-реле и проверьте сервер.
[Развёртывание и обновление](VPS_RELAY.md). Исправленный Worker 0.4.2 менять не нужно.

## Совместимость и зависимости

Перенесены проверенные обновления из PR #27–30: WorkManager 2.12.0, Core KTX 1.19.1,
JSON-java 20260814 только для JVM-тестов, setup-java 6.1.0 с commit SHA.
Kotlin/AGP/Wrapper/JDK/SDK не менялись. Нет новых runtime-зависимостей, WebView,
VPN, встроенного Cloudflare DNS, SSH-клиента или дополнительных wake locks.
Существующий warm pool не перевыпускает соединения без спроса; Saver исключает прогрев.

Старые записи транспорта из 5/6 строк читаются и кодируются без изменения.
Список реле — необязательная седьмая строка существующего AES-GCM record с прежним
AAD/Keystore. Общий plaintext ограничен 32 КиБ для совместного списка Worker/реле;
проверены максимальная конфигурация, подмена ciphertext и сохранение ключей.

## Приёмка владельцем

1. Установить APK поверх совместимого Debug, не удаляя приложение. Сверить code 22,
   секрет/порт/старый URL/профили/оформление и параметры обновлений.
2. Сначала проверить старый режим с выключенным менеджером. Добавить основной и
   резервный VPS, явно включить менеджер и сохранить. Проверить ручной/резервный/
   автоматический выбор; неисправный основной не должен блокировать разрешённый резерв.
3. «Только реле» и MANUAL не должны открывать запрещённый прямой маршрут.
   Проверить доступность узла и отмену проверки при уходе с экрана/смене сети.
4. Проверить Wi-Fi/LTE и обе смены сети, сообщения, SD/HD-фото, кружки, видео и
   файлы более 16 МиБ в обе стороны. Для Worker отдельно учитывать BYTE_LIMIT.
5. Проверить фон 30–60 минут, start/stop, повторное открытие, поворот, удаление/редактирование
   узлов. Остановка должна освобождать порт, сессии и уведомление.
6. Сообщить в чат версию/режим/направление/шаг/итог и безопасный JSON из диагностики.
   Не публиковать личные данные, адреса, токены, названия приватных узлов и секрет.

Quick Settings Tile остаётся запланированным: ограничения FGS и физическая приёмка
требуют отдельной проверки. В этот релиз не добавляется неработающий переключатель.
