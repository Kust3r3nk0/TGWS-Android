# Проверка 0.2.0-alpha

Эталон: Flowseal/tg-ws-proxy **v1.11.2**, commit
`307a384ab7f522e34bb1a045884d0bd90f40bee5`. [English](en/TESTING.md).

## Автоматические проверки

Используйте JDK 17, Android SDK `platforms;android-37.0` и
`build-tools;36.0.0`. Версии Gradle, AGP и Compose compiler закреплены
в репозитории; не заменяйте их для обхода сбоя проверки.

```bash
./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Эталонные векторы должны получаться из неизменённых функций закреплённого
upstream, с управляемой случайностью. Python используется только в тестовой
среде и не входит в APK. Повторно сгенерированные данные необходимо сравнить
с закоммиченными векторами, а не автоматически переписывать при сбое теста.

JVM-тесты проверяют криптографию, framing, локальный listener, ограниченный
fallback и локальный WebSocket-сервер. Они не подтверждают доступность
публичных серверов Telegram из конкретной сети.

## Android

Проверьте API 35, 36 и 37 при наличии стабильного system image.
Инструментальные тесты требуют подключённого устройства или эмулятора:

```bash
./gradlew --no-daemon :app:connectedDebugAndroidTest
```

CI дополнительно запускает `python3 .github/scripts/verify_android_tests.py`:
проверяются записи всех 14 тестов, а не только exit code Gradle. Пустые отчёты,
пропуски, повторяющиеся записи и любой failed/error не засчитываются. Саму
проверку и настройку эмулятора проверяет
`python3 -m unittest discover -s .github/scripts -p 'test_*.py'`.


Ручная матрица для каждого API:

| Сценарий | Что проверять |
|---|---|
| Первый запуск | Секрет скрыт; listener не запускается сам |
| Запуск и остановка | Локальный порт открывается и освобождается; уведомление удаляется |
| Сворачивание и возвращение | Сервис продолжает работу; UI показывает фактическое состояние |
| Повторный запуск сервиса | Нет второго listener и повторных потоков |
| Занятый порт | Понятная ошибка; foreground service завершается |
| Нет интернета | Локальный listener и удалённые сессии различаются; попытки ограничены |
| Неверный secret | Конфигурация отклоняется; новый секрет сам не появляется |
| Поворот и повторное открытие | Порт, скрытие секрета и состояние сервиса корректны |
| Утеря ключа Keystore | Ошибка видна; сохранённый ciphertext не заменяется без действия пользователя |
| Потеря Wi-Fi / мобильной сети | Старые сессии закрываются; Telegram может создать новые |

Тип foreground service `specialUse` используется для запущенного пользователем
локального прокси с постоянным уведомлением. Это не VPN. При распространении
через магазин требуется отдельная проверка его правил для этого типа сервиса.

## Реальный Telegram E2E — release gate

Нужно физическое устройство Android 15+ с официальным Telegram.

1. Установить APK; записать его SHA-256 и commit сборки.
2. Запустить прокси; передать локальную `tg://proxy` ссылку кнопкой приложения.
3. Включить этот прокси в Telegram и подтвердить установление соединения.
4. Отправить и получить текстовое сообщение.
5. Кратко отключить сеть, восстановить её и проверить повторное соединение.
6. Проверить Wi-Fi и мобильный интернет отдельно.
7. Остановить прокси; проверить завершение сессий и освобождение порта.

Для отчёта заполнить:

```text
Дата UTC:
Git commit:
TGWS-Android version: 0.2.0-alpha
APK SHA-256:
Устройство / Android / API:
Официальный Telegram version:
Сеть (без персональных адресов):
Оператор / страна (для мобильной сети):
Режим: прямой / WSS-реле (URL с ключом не публиковать)
Подключение через прокси: PASS / FAIL / NOT RUN
Отправка текста: PASS / FAIL / NOT RUN
Получение текста: PASS / FAIL / NOT RUN
Восстановление сети: PASS / FAIL / NOT RUN
Остановка и освобождение порта: PASS / FAIL / NOT RUN
Примечания (без секретов и содержимого сообщений):
```

До подтверждения этого сценария нельзя заявлять о полностью проверенном
рабочем прокси. Владелец разрешил явно обозначенные debug-предрелизы после
автоматических проверок; это не прохождение стабильного release gate.
Для стабильного пользовательского релиза нужна доверенная подпись.

## Реле и мобильная сеть

`npm ci --ignore-scripts --prefix relay && npm test --prefix relay` проверяет
сервер реле с настоящими локальными TLS/WSS/TCP соединениями. Эти тесты не
проверяют доступность IP у оператора. Отдельно повторите E2E с прямыми
маршрутами и с настроенным собственным реле при выключенном Wi-Fi; сравните
результаты и проверьте возврат из relay-only в direct после очистки URL.
Убедитесь, что недоступное реле завершается по deadline без прямого fallback,
а потеря ключа Keystore требует явного восстановления URL.
[Настройка внешнего узла](MOBILE_NETWORKS.md).

Нагрузочный прогон 0.2: добавьте `-PsoakSeconds=180` к Wrapper-команде (1–3600 с; CI 60 с). [Политика и стенд](RELIABILITY_0.2.md).
