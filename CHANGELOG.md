# TGWS-Android 0.6.2 — Автонастройка сети · Debug

Android 16+ / API 36+, code 24. Тестовый Pre-release.

## Новые функции

- Настройки → Smart Connection → «Автонастройка текущей сети»: одна кнопка запускает ограниченную проверку разрешённых маршрутов и сохраняет профиль Wi-Fi/мобильной сети.
- Проверяется ответ req_pq_multi от DC 2: Obfuscated2, размер/тип resPQ и nonce, а не только TCP/TLS/Upgrade. Это проверка доступности MTProto без аккаунта, не авторизация Telegram и не измерение ping.
- Основной транспорт выбирается по успешному ответу и времени полного обмена; разрешённые резервные маршруты сохраняют backoff и право последующего восстановления.
- Видны прогресс, категории отказов и HTTP-коды; проверку можно отменить.

## Исправления

- Учёт входящего трафика до передачи клиенту устраняет гонку финального счётчика при остановке после крупного файла.

## Важное

Остановите прокси перед автонастройкой. Приложение использует только настроенные адреса и разрешённые транспорты текущего режима; «Только реле» не обходит запрет прямого подключения. Секрет, локальный порт и Fake TLS/SNI не подбираются случайно и не меняются: их изменение нарушило бы ссылку Telegram. Тема и остальные пользовательские настройки сохраняются.

Проверка занимает до 60 секунд, до 8 секунд на маршрут, без фонового повторения; повторный запуск не чаще раза в минуту. Смена сети, уход с экрана или сворачивание отменяют проверку и закрывают ресурсы. Без успешного ответа прежняя конфигурация сохраняется. При ошибке сохранения показывается ошибка, черновик восстанавливается.

Проверяются до двух разрешённых узлов каждого настроенного вида; сначала один кандидат каждого вида. HTTP/2 media не проверяется и не выбирается основным. Успех DC 2 не гарантирует остальные DC, HD-медиа или отсутствие ограничений Worker (16 МиБ/сессию). Успешный Worker перемещается первым в сохранённом списке; успешный VPS становится основным среди разрешённых узлов — эти приоритеты адресов общие для профилей. Сами адреса не создаются и не удаляются. Профили различают тип сети, а не конкретный SSID/оператора.

Автонастройка не создаёт внешнее реле и не снимает блокировку, если ни один разрешённый маршрут не доступен. В таком случае показаны причины отказов. Worker/Node относительно 0.6.0 менять не требуется. Установить APK поверх совместимой подписанной Debug-сборки без удаления приложения; проверить запуск, переключение сетей и Telegram. Физическую проверку выполняет владелец, без публикации личных данных.

- Слот подключения освобождается после подтверждённого закрытия TCP/WS; shutdown закрывает незавершённый TLS.
- Уведомления о резерве различают разные узлы одного транспорта; приватные адреса в журнал не попадают.

## Техническое

- Сценарий VPS-развёртывания, systemd unit, ограниченные переменные среды и инструкция обновления с сохранением токена/TLS.

## Важное

Менеджер включается явно: Настройки → Транспорт → Менеджер VPS-реле. После добавления
сохраните настройки. Прямой режим не использует реле; MANUAL/«Только реле» не обходят
выбранные ограничения. Уже начатый поток не переносится на другой сервер.
Обновите собственное Node.js-реле для серверных исправлений; APK сервер не обновляет.
Worker остаётся прежним: 6 сессий/isolate и 16 МиБ/сессию. Исправленный Worker 0.4.2
не требует redeploy. Работа реального Telegram/HD/mobile проверяется владельцем.

## 0.4.2 — Relay Stability Fix

## Важное

TGWS-Android 0.4.2 — Relay Stability Fix. Тестовая сборка для Android 16+,
code 20; готовность Production не заявляется. Для всех исправлений реле
обновите **APK и код существующего Cloudflare Worker**.

## Исправления

- Общий setup deadline больше не расширяется до 40 с; WSS-попытки оставляют ограниченный резерв для разрешённого TCP fallback.
- INVALID_LENGTH получает подсказку о неполном заголовке, отдельно от неверного секрета и неподдерживаемого формата/DC.
- Ранний обрыв после Upgrade больше не обходит маршрутный backoff; повторные
  исходы одной попытки не увеличивают паузу дважды. Пауза восстанавливается
  по фактическим входящим данным, а не одному открытому сокету.
- HTTP 429/503 одного endpoint учитываются совместно для разных DC, с
  ограниченным Retry-After и единственной проверкой восстановления.
- Код и безопасная причина WebSocket Close сохраняются даже при ошибке echo.
- Обычный клиентский EOF отправляет ограниченный WS Close до закрытия сокетов.
- Смена сети закрывает WSS/TCP scope, включая сокеты в TLS handshake.
- Worker освобождает stream-lock при сорванном Upgrade и ждёт подтверждения
  закрытия TCP и WS перед допуском замены. Binary mode/handlers устанавливаются до accept.
- Закрытие одной сессии не скрывает другой работающий сеанс того же маршрута.

## Техническое

- JSON schema 3 и существующий журнал: HTTP Upgrade, фиксированная причина
  Worker, пауза, номер и причина завершения каждой сессии, duration/bytes/Close.
- HTTP 503/CAPACITY и CONFIGURATION различаются; TCP setup — 502/UPSTREAM_CONNECT
  либо 504/UPSTREAM_TIMEOUT. Приватные HTTP body/URL/reason text не журналируются.
- В CI доступен отдельный модуль Worker с checksum и source/checked commit.
- Настройки, секреты, UI, TLS-проверки, системный DNS и Android 16+ сохранены.

## Общее сведение

Лимиты Worker не повышены: 6 сессий/isolate, очередь 4 МиБ + 4 Б,
64 сообщения, 16 МиБ суммарно/сессию. BYTE_LIMIT и IDLE_TIMEOUT остаются видимыми
причинами закрытия. Крупные медиа всё ещё могут достигать лимита.
Исправления покрываются автоматическими регрессиями; реальная устойчивость
внешнего Worker/Telegram проверяется владельцем после установки.

## 0.4.1 — расширенная диагностика

Тестовое обновление на базе кандидата 0.4.0 / PR #22. Android 16+, code 18, прежние applicationId, формат настроек и ключи. Production-публикация не выполняется.

## Новые функции

- Категории журнала: служба, конфигурация/хранение, сеть, DNS, TLS, TCP, WebSocket, реле, HTTP/2, маршруты, MTProto-клиенты, локальная проверка и системный WebView.
- Уровни INFO / WARNING / ERROR, сочетание фильтров, счётчики повторов, время первого и последнего события. История до 128 записей и 32 реальных замеров, только в памяти.
- Детали маршрута: DC/media, транспорт, этап, попытки, измеренные DNS/TCP/TLS/HTTP, Close-код и безопасная категория причины. Неизмеренные этапы остаются пустыми.
- Однократная проверка выбранного порта 127.0.0.1 с отменой. Она не передаёт секрет и не подтверждает MTProto-аутентификацию или Telegram.
- Подсказки по наблюдаемой проблеме: captive portal, секрет/порт, DNS, TLS, реле, восстановление сети и известный лимит Worker.
- Предпросмотр, копирование и явная отправка JSON-файла отчёта. Секреты, адреса реле/IP/DNS, оператор и сообщения исключены.

## Исправления

- Переподключение очищает замеры предыдущей попытки.
- Вложенные ошибки DNS/TLS/TCP классифицируются по ограниченной цепочке причин, включая защиту от циклов.
- Отказы и закрытия маршрутов, повторные ошибки и причины MTProto handshake больше не теряются за одной общей строкой.
- При отмене локальной проверки закрывается сокет; позднее завершение отменённого запроса не меняет индикатор новой проверки.

## Оптимизация

- Повторные предупреждения объединяются за окно 10 секунд. Для logcat выводятся повторы 1, 2, 4, 8…; новые успешные измерения не объединяются.
- Фильтрованный журнал рисуется через LazyColumn. Проверки выполняются только по действию; монитор пакета работает только в видимой Activity.

## Техническое

- WebView: читаются доступность, пакет, точная версия и канал по известному имени; изменения фиксируются при возврате в приложение, обновлении выбранного пакета и ручном обновлении сведений.
- Используется документированный metadata-only API `getCurrentWebViewPackage()`: движок не загружается, WebKit-зависимость и веб-интерфейс не добавляются. Страниц и renderer в TGWS нет, их журналы неприменимы. Чужие приложения и их логи недоступны.
- Не утверждается Latest Stable/Beta: версия фиксируется фактически установленная, неизвестный OEM не считается Stable. Новые числовые версии не ограничены жёстким порогом.
- TLS, системный DNS, сетевые транспорты, Keystore и безопасный Update Center сохраняются. Встроенный Cloudflare DNS не возвращается.
