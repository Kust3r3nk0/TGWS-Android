# История изменений

Все значимые изменения проекта будут фиксироваться здесь. Формат основан на Keep a Changelog; версия — в духе Semantic Versioning.

## [0.3.0-alpha] — 2026-10-16 (debug)

- Этапы 0.3/0.4 объединены: Fake TLS HMAC/records и ee-ссылки, конфигурация CF Proxy/Worker, совместимый HTTP/2 media `/api`.
- Режимы direct, relay-only и Auto CF; Worker → CF → TCP, ограниченная ротация/backoff, без replay. Relay-only не открывает прямой путь.
- HTTP/2: строгий TLS/ALPN, два запроса на native-сессию, ограничение очередей/ответов, flow control, RST/GOAWAY/cancel. Добавлен стабильный OkHttp 5.5.0; остальной стек сохранён.
- Привязка DNS/сокетов к Android Network, IPv4/IPv6/DNS64 средствами ОС; отмена при смене сети. Callback lifecycle без дополнительных wake locks.
- Диагностика этапов/маршрутов/сети/трафика, фактические DNS/TCP/TLS/HTTP замеры, ручной probe и обезличенный экспорт с предпросмотром. Исправлены замеры TLS при конкурентном выборе адресов.
- Справочник четырёх российских операторов без изменения APN/DNS/SIM; data-SIM и PLMN регистрации не смешиваются. Новые параметры защищены Keystore; настройки 0.2 мигрируют без смены режима.
- Сохранены прежние тесты; добавлены векторы upstream, локальные TLS/H2/Fake TLS и Android migration/cleanup тесты; обязательные TCP/WSS и H2 soak в CI.
- versionCode 6, Android 15+, прежние applicationId/логотип/debug-сертификат. Проверка владельцем на физическом устройстве: ожидается. Мобильные операторы и внешние CF/Worker E2E не проверены; гарантия обхода не заявляется.

## [Unreleased] — Cloudflare Worker, отдельно от APK

- Серверная экспериментальная заготовка Worker для имеющегося WSS relay-клиента: фиксированные DC/IP, ключ пути, тайм-ауты, очередь, очистка ресурсов и явный лимит 16 MiB на сессию.
- Локальные тесты, bundling стабильным Wrangler и CI-артефакт готового модуля. Новый APK не требуется; Android-код/версия/подпись не менялись.
- Инструкция RU/EN: реальный Worker SNI вместо подстановки чужого `cloudflare.com`. Развёртывание в аккаунте владельца и Telegram E2E в Мегафоне Москва/область не выполнены. Шаблон может прерывать большие загрузки и не обозначается как исправление стабильности.

## [0.2.0-alpha] — 2026-10-15 (debug)

- Одноразовый пул ещё не использованных прямых WSS-подключений: четыре в сумме, один сокет на маршрут, два фоновых connect-потока, 30 с свежести. Перед init проверяется совпадающий Pong; активные MTProto-сессии не переиспользуются.
- Ротация и очистка по смене сети/stop; отменённые и запоздавшие сокеты закрываются. Нет бесконечного фонового refill без спроса. Relay и TCP не прогреваются.
- Per-route backoff setup-отказов 1–30 с, одна проверочная попытка после паузы, защита от запоздалых результатов и сброс при смене сети. Без replay MTProto payload.
- Тесты пула, Ping/Pong и backoff; стенд с реальными локальными TCP/TLS/WSS, ef/ee/dd, длительными CTR-потоками, конкурентными клиентами и сетевыми сбросами. CI включает 60-секундный soak.
- Эталон Flowseal v1.11.2 и стабильные зависимости сохранены; versionCode 5, Android 15+.
- Реальные Telegram 0.2.0, Wi-Fi/LTE и внешний relay E2E требуют проверки. Стабильный release gate не пройден.

## [0.1.3-alpha] — 2026-10-15 (debug)

- Собственное WSS-реле по Worker-контракту Flowseal: фиксированные dst/dc, 64-байтовый relay init и прежний Obfuscated2. Выбираемый режим без прямого fallback, отдельный счётчик.
- URL реле скрыт в UI и защищён отдельной AES-GCM записью с AAD в Keystore; утрата ключа требует явного восстановления.
- Ограничены DNS-ожидание, число resolver-потоков и очередь; зависший DNS не удерживает клиентский поток бесконечно.
- Добавлен самостоятельный сервер WSS-реле для собственного хоста: TLS, ключ пути, только Telegram DC, stream backpressure, лимиты и тесты с настоящим локальным TLS/TCP. Сервер не входит в APK.
- Мобильный внешний маршрут требует вашего доступного узла. Деплой и Telegram E2E у реального оператора не выполнены; обход блокировки не заявляется подтверждённым.

## [0.1.2-alpha] — 2026-10-15 (debug)

- Логотип владельца добавлен в приложение и README; adaptive launcher icon и отдельный монохромный значок уведомления.
- Название установленного приложения — TGWS-Android, без Alpha. versionCode 3; стадия alpha сохраняется в версии.
- Минимальная ОС повышена до Android 15 / API 35; текущая CI-матрица API 35–37.
- Отказ handshake классифицируется без записи данных заголовка/секрета. Счётчик отклонённых клиентов не подменяет ошибки сервиса и сети; секрет и маршрутизация проверяются строго как прежде.
- Обновлены постоянные инструкции, ТЗ-сводка и roadmap; разрешена публикация проверенных debug-предрелизов с известными ограничениями.
- Пользователь подтвердил работу 0.1.1-alpha и сообщил о 6–8 мс в Telegram; это не независимая проверка задержки или полной матрицы E2E.

## [0.1.1-alpha] — 2026-10-15 (тестовая сборка)

### Исправлено
- Живые WSS-сессии больше не закрываются через один общий 60-секундный срок ожидания: Ping/Pong обновляют ожидание, при тишине отправляется Ping с ограниченным сроком ответа.
- Срок сборки фрагментированного сообщения и ограничения памяти сохраняются; зависший peer закрывается, неверный Pong не подтверждает heartbeat.
- Заголовок, маска и данные WebSocket буферизуются перед TLS-записью; включён TCP_NODELAY.
- Предел бездействия MTProto-сессии увеличен с 60 до 300 секунд; сроки handshake/connect/write не изменены.
- После успешного нового соединения снимается устаревшая ошибка fallback. При работающих сессиях ошибка другой сессии показывается как последнее событие; отдельные счётчики WSS/TCP показывают фактический транспорт.
- versionCode увеличен до 2; имя CI-артефакта берётся из versionName.

### Проверки и ограничения
- Пользователь подтвердил отправку, получение и загрузку в **0.1.0-alpha**: Android 16, Telegram 13.0.2, Wi-Fi. Сообщил о кратких обрывах. Это не подтверждает исправление в новой сборке.
- Обновление 0.1.1-alpha требует повторной проверки на том же устройстве; причины всех реальных разрывов пока не установлены. Подробности: [отчёт](docs/TEST_REPORT_0.1.1-alpha.md).

## [0.1.0-alpha] — 2026-10-14
### Добавлено
- Первый публичный исходный код Android-порта на Kotlin.
- Интерфейс на Jetpack Compose.
- Первичная реализация локального MTProto-прокси, WSS и TCP fallback.
- Foreground Service, настройки и Android Keystore.
- Модульные тесты, документация, MIT License и конфигурация CI.

### Ограничения
- Debug APK и автоматические тесты API 34–37 прошли CI; физическое устройство и реальный Telegram пока не проверены.
- Fake TLS, Cloudflare-маршруты и HTTP/2 пока не перенесены.
- Подписанные APK и стабильные релизы отсутствуют.

### Исправлено в подготовке альфы
- Проверка MTProto handshake, границ пакетов и сохранение независимых AES-CTR состояний; добавлены воспроизводимые побайтовые векторы Flowseal v1.11.2.
- RFC 6455: masked server frames, RSV, continuation, длины, Upgrade, Ping/Pong и Close; конечные тайм-ауты и сохранённая проверка TLS.
- Разделены WSS redirects и TCP-маршруты; ограничены попытки fallback, сессии и фоновые потоки; сокеты закрываются при остановке и потере сети.
- Повторный запуск foreground service не пересоздаёт listener; состояние локального сервера отделено от транспортных сессий.
- Секрет скрыт по умолчанию; ошибки Keystore требуют явного восстановления; добавлены RU/EN Android-ресурсы и проверка Telegram-ссылок.
- CI закреплён по SHA, публикует checksum, build metadata и отчёты; добавлены инструментальные тесты и отдельная матрица Android API 34–37.
- CI отклоняет пустые и неполные Android-отчёты, проверяет фактический API эмулятора; исправлены запуск зависимых shell-команд и метаданные AVD API 37.0, добавлены 16 тестов CI-скриптов.
- Версия остаётся `0.1.0-alpha`; физический Telegram E2E не выполнен, tag и Pre-release не создаются до прохождения release gate.
