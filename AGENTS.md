# Инструкции для Codex — TGWS-Android

Основной язык документации и отчётов: **русский**. Английские материалы размещайте отдельно в `docs/en/`.
English guide: [docs/en/CODEX_WORKFLOW.md](docs/en/CODEX_WORKFLOW.md).

## Назначение и границы

- Это **Android-приложение локального MTProto WebSocket-прокси**, а не системный VPN. Не меняйте назначение проекта без явного требования.
- Исполняемый код: Kotlin, Jetpack Compose, Android foreground service и сетевое ядро.
- Поддерживаемая версия Android: **16+ (minSdk 36)**. Фактические версии AGP, Kotlin, Gradle, compileSdk и targetSdk берите из файлов Gradle, а не из устаревшего текста документации.
- Текущая реализация — **alpha**. Не представляйте наличие исходников, компиляцию или JVM-тесты как доказательство работы прокси на реальном устройстве.

## Один запрос с ТЗ — один проход реализации

Если пользователь передал ТЗ и разрешил изменять проект:

1. Ознакомьтесь с `README.md`, `ROADMAP.md`, `CONTRIBUTING.md`, `SECURITY.md` и только с теми исходниками, которые относятся к задаче.
2. Выделите обязательные требования и зависимости между ними. Составьте короткий план и **переходите к реализации**, не запрашивая подтверждение обычных действий, уже разрешённых в окружении.
3. Реализуйте законченные функциональные блоки в рамках ТЗ. Сохраняйте работающее поведение и избегайте необоснованного рефакторинга.
4. Добавьте целевые тесты на изменённую логику, прежде всего на MTProto, WebSocket, ошибки сети и жизненный цикл Android, когда это применимо.
5. Проверьте изменения, исправьте обнаруженные ошибки и повторите необходимые проверки. Если подход не работает, проанализируйте первопричину, а не повторяйте одну и ту же команду.
6. Сохраните изменения в отдельной ветке и подготовьте PR с результатами, выполненными проверками и известными ограничениями, если создание PR доступно в текущем окружении.

Не останавливайтесь после одного файла или этапа, если остаются реализуемые требования и ресурсы. Не утверждайте, что ТЗ выполнено полностью, если остались невыполненные пункты.

## Сборка и качество

В корне репозитория используйте **Gradle Wrapper** и JDK 17:

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Windows: `gradlew.bat`. Для CI также требуется Android SDK с платформой, соответствующей `compileSdk`.

Ожидаемый путь Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. В GitHub Actions артефакт загружается автоматически после успешных проверок. **Debug APK — не подписанный для публичного релиза пакет**: он может содержать стандартную отладочную подпись, но не является production-релизом.

- При небольших изменениях сначала запускайте целевые тесты; перед финальной сдачей выполняйте полный набор проверок выше.
- Проверка на физическом устройстве, реальное подключение к Telegram, тесты Fake TLS и сетевые E2E-тесты подтверждаются только тогда, когда они действительно проведены.
- Если SDK, сеть, разрешения или лимит агента мешают проверке — укажите это явно; не придумывайте результаты и не скрывайте ошибки.
- Не заменяйте обязательную функциональность заглушками и не отключайте тесты, Lint или проверки TLS ради «зелёной» сборки.

## Безопасность и Git

- Следуйте `SECURITY.md`: не публикуйте ключи, MTProto secrets, токены, данные пользователей, private endpoints, логи с конфиденциальными данными и ключи подписи APK.
- Не ослабляйте проверку сертификатов TLS и не делайте listener общедоступным по умолчанию.
- Работайте в отдельной ветке. Не выполняйте force-push, не объединяйте PR в `main`, публикуйте разрешённые пользователем debug-предрелизы после проверок; стабильный APK публикуйте только после прохождения release gate ТЗ.
- Не устанавливайте произвольные сторонние скрипты и не проводите внешние действия без разрешений окружения.

## Экономия контекста и квоты

- Читайте связанные с задачей файлы и используйте уже известные результаты, не сканируйте весь репозиторий на каждом шаге.
- Не тратьте время на избыточные отчёты, ненужное переписывание документации и циклические полные сборки.
- По возможности заканчивайте один проверяемый блок перед переходом к следующему.
- Если время или квота заканчиваются: оставьте воспроизводимое состояние проекта, зафиксируйте готовое, перечислите оставшиеся требования и точную команду следующей проверки.

## Актуальные указания владельца (обновлено 19 октября 2026)

- Дальнейшая разработка только Android 16+ / minSdk 36. В текущем дереве не хранить ресурсы, инструкции, изображения и отчёты для неподдерживаемых ОС; историю Git не переписывать.
- Логотип предоставлен владельцем; подпись установленного приложения — `TGWS-Android`, без `(Alpha)`. Стадия alpha остаётся в versionName и документации до её фактического завершения.
- Владелец разрешил публиковать релизы и debug-релизы. После успешных проверок обновляйте GitHub, changelog и план, публикуйте debug APK как явно обозначенный GitHub Pre-release с checksum и commit. Не выдавайте debug-подпись за production.
- Проверки: полная Wrapper-команда, CI и матрица API 36/37; сравнивайте реальные JUnit-записи. Стабильный релиз требует полного E2E и доверенной подписи.
- Для последующих debug-релизов используйте уже сохранённый локальный debug-ключ вне репозитория (в текущей среде `/workspace/private-signing/tgws-debug.keystore`), если он доступен; проверяйте сертификат. Не заменяйте его молча новым и не выгружайте ключ в GitHub. CI APK может иметь другую временную подпись.


## TGWS-16-016 / TGWS-16-017 (16 октября 2026)

- [WebView](docs/TGWS-16-016_WEBVIEW.md): текущий UI нативный Compose, встроенного WebView нет. Не добавлять WebKit/скрытый WebView без реального веб-интерфейса; MTProto не зависит от браузера/JavaScript. Новая интеграция требует отдельной реализации provider/feature checks, безопасности/renderer recovery и матрицы Stable/Beta; контрольная стабильная зависимость из ТЗ — WebKit 1.17.1, после проверки доступности/совместимости. Dev дополнителен, Canary экспериментален.
- CI-инвентаризация WebView-пакета/версии не подтверждает Latest Stable/Beta. Не выдавать AOSP или неизвестный OEM за проверенный Stable. Общий minSdk — 36; все новые испытания и WebView-матрицы начинаются с Android 16.
- [Физическое тестирование](docs/TGWS-16-017_PHYSICAL_TESTING.md) полностью выполняет владелец. Не искать его смартфоны, не просить ADB/доступ к ним, не задерживать разрешённый debug-предрелиз ожиданием телефона. Codex выполняет автоматические unit/integration/CI/Lint/build проверки и исправляет подтверждённые ошибки с повторной регрессией.
- Передавать конкретную ссылку Actions/artifact, версию, source SHA и checked tree SHA, checksum и changelog. Использовать `OWNER_HANDOFF.md`/шаблон отчёта, отмечать физические результаты только по сообщению владельца. Не публиковать секреты, ключи, private relay URL, сообщения и идентификаторы телефона.
- One UI 8.5/9.0, Stable/Beta, Live Updates/Quick Settings и реальные транспорты зависят от устройства и фактически реализованных функций; неприменимые/неподдерживаемые сценарии не отмечать пройденными. Успешный APK не означает стабильный production-релиз.

## Уточнение владельца: сети (16 октября 2026)

- Встроенный Cloudflare DNS удалён начиная с 0.3.4. Используйте resolver активного Android Network; не возвращайте публичный DNS/DoH в production без нового требования. Исторические DoH fixtures остаются только в тестах.
- Существующие настроенные Cloudflare/Worker-транспорты сохраняются: удаление DNS не означает удаление реле. Не обещайте снятие IP/SNI/allowlist ограничений одним DNS или Fake TLS локального listener.
